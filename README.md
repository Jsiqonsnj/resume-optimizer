# 简历优化工作台 · Resume Studio

零构建、零依赖的中文简历优化网页应用。双击 `index.html` 即可运行，不需要 npm、不需要构建、不需要服务器。

当前进度：**阶段 4 已交付**（新增「深审」页：逐行过七关 —— 会被怎么问 / 够不够细 / 真不真实 / 缺什么 / 该删什么 / 有没有 AI 味 / 逻辑通不通，结论全部锚到行号）。此前阶段 2.5 接入了 `resume_engine` 专业引擎。

---

## 运行

1. 双击 `index.html`（Chrome / Edge / Firefox 均可）。
2. 左侧六个 Tab：上传 / 知识库 / 审阅 / 深审 / 优化 / 规划（后四个放进简历才出现）。
3. 想直接看效果：上传页点「载入示例简历」，会同时把示例 JD 一起塞进去。

## 接入 resume_engine（阶段 2.5）

原来的规则引擎只能抓「有没有数」「动词弱不弱」，判断不了岗位族、职级、空窗、行业特征词，也没有改写骨架。`D:\破甲后\resume_engine` 是一套成熟的 Python 引擎（2795 行），现在整体搬进前端：

| 做法 | 说明 |
| --- | --- |
| 词表不手抄 | `tools/extract-engine-data.py` 直接 import Python 包，导出 16 职能族 / 10 行业 / 307 个 JD 词条 / 6 个 demo 到 `js/engine-resume/lexicon.data.js` |
| 逻辑 1:1 移植 | `parse / signals / profile / jd-match / diagnose / rewrite / interview / score / report / review` 逐函数对照 Python 写，`pyRound` 复刻 Python 的银行家舍入 |
| 可验证而非「看着像」 | `tools/parity.py` 用 Python 跑 10 个 case 存成黄金样本，`tools/parity-js.js` 在 `vm` 沙箱里跑 JS 版逐字段比对（四层诊断 / 五维分 / 改写 / 追问 / 自我介绍 / Markdown 报告），当前 10/10 一致 |
| 前端只做展示 | `report-view.js` 不重算任何判断，引擎给什么画什么 |

契约（`analyze` / `refine` 的入参与返回结构）保持阶段 0 的冻结版本不变，所以阶段 1/2 的上传、圈画、追问清单、格式批注全部照旧工作。

### 六页分工：上传 / 知识库 / 审阅 / 深审 / 优化 / 规划

导航不是一次给六个入口。**放进简历之前，左侧只有「上传」和「知识库」**；一旦简历载入（`state.resumeText` 有 20 字以上），审阅 / 深审 / 优化 / 规划才出现，并自动跳到审阅。清空简历会重新上锁 —— 没料的时候给入口，只会让人点进去看空页面。

门控落在两处：`index.html` 给这四个按钮加 `data-gate="1" hidden`，`main.js` 的 `GATED` + `applyGate()` 按「有简历 = 解锁」统一开关，`setTab()` 遇到锁着的 Tab 直接回退到上传并 toast 提示。

| 页 | 回答的问题 | 给什么 |
| --- | --- | --- |
| 上传 | 料怎么进来 | 拖拽 / 选文件 / 粘贴；顺带采集字号、页数、空行、字体、日期格式这些「改不了但会扣分」的排版信号 |
| 知识库 | 我这个行业 HR 在看什么 | 26 大类 / 80 方向的关键词、过筛标准、常见坑、写法建议 |
| 审阅 | 我这份哪里有问题、会被怎么问 | 圈画纸 + 引擎总评（分 / 档 / 五维 / JD 雷达 / 六秒测试）+ 疑问清单 + 四层诊断 + 追问预演（面试会怎么问）+ 亮点 |
| 深审 | 逐行看，这一行会被怎么问 | 七项体检（详细度 / 该补 / 真实性 / 语言 / 追问防御 / 该删 / 逻辑）+ 逐行过堂卡片：每行七块（会被这么问 · 够不够细 · 真不真实 · 该补什么 · 该删什么 · 语言与 AI 味 · 逻辑），追问可标「已备答」，可导出九节 Markdown 报告 |
| 优化 | 这句话该怎么改 | 把可优化的句子逐条摘出来，**用提问的方式要材料**：「你管的盘子多大」「你动过哪个指标」「从多少做到多少」；答完按「规模 → 我负责的动作 → 结果」拼成一句能直接替换的话，附骨架、例句与复制；同页还有整份重排与报告导出 |
| 规划 | 差什么、怎么补、多久补完 | 无需点按钮，进页即出：定位（行业 / 职能族 / 职级 / 一句话卖点）+ 缺口（JD 缺失词 + 行业特征词未命中 + 硬伤）+ 三档拔高（A 补证据 / B 补资质 / C 补表达）+ 一周内能补的 + 3 / 6 / 12 个月阶梯 + 面试疑点备答 |

为什么「审阅」和「优化」要分开：**审阅是判断，优化是执行**。判断只需要给结论和理由，不该顺手改字；执行需要逐句问出事实，因为简历里缺的往往不是文笔而是「你具体做了什么」。两件事塞在一页，用户会跳过判断直接抄例句 —— 抄出来的句子看着漂亮，一问就露。

优化页拼句的边界：**不填空骨架、不编数字**。引擎骨架的槽位和问题并不是一一对应的（运营族第二条骨架有 5 个槽却只有 3 个问题），硬填空会拼出「搭建/运营 3 个社群共 1200 人社群/账号」这种句子。所以拼装改用固定三段式，骨架与范例只作参考展示；哪个问题没答，就明说「这格 HR 一定会问」。

规划页的数据来自三处，不是通用课程表：`js/plan-data.js`（人工整理：16 职能族的可验证证据、10 行业真会卡人的资质、30+ 缺口词的一周补法、3/6/12 月规则）+ 引擎识别的行业 / 职能族 / 职级 / 缺口 + 四层诊断里的硬伤。

| 卡片 | 内容 |
| --- | --- |
| 引擎总评 | 总分 + 档位（A~D）+ 一句话建议；致命问题会压分，并写明「原始分 X，因 N 处致命压到 Y」 |
| 画像 | 应聘类型（校招 / 社招 3+ / 转行 / 管理）、行业、职能族、工作月数、段数，以及画像上的坑 |
| 五维分 | 内容有效性 / 可读性 / 对岗度 / 可信度 / 结构完整度，各带一条现场证据 |
| JD 雷达 | 关键词覆盖率、该投 / 勉强 / 别投的裁决、硬门槛核查、缺失词 |
| 六秒测试 | 只看前 420 字能不能抓到「做什么 + 最强一件事」，缺什么直接列出来 |
| 四层诊断 | 内容无效 / 读不下去 / 对岗不投 / 面试会挨打，每层只给最狠的一条（怎么改 + 原文证据），同层其余折叠 |
| 追问预演 | 面试会怎么问（亮点 / 疑点 / 稳定三类），答案骨架，可标记已备答 |
| 逐句问答 | 原句 → 我的追问（三个）→ 你答 → 生成能替换的一句 + 缺格提醒 + 骨架参考 |
| 拔高路线 | 定位、缺口、三档建议、一周动作、3/6/12 月阶梯、面试疑点备答、一句话卖点、60 秒自我介绍 |
| 导出 | Markdown 报告（与 Python 端 `report.to_markdown` 同一套模板），下载或复制 |

### 五维雷达（纯 SVG）

`js/radar.js` 只做三件事：算五个顶点、拼网格环、拼标签。没有图表库、没有 `<img>`、没有外部字体 —— 在 268×236 的 viewBox 里现算，任何缩放下都清晰。

| 细节 | 处理 |
| --- | --- |
| 比例 | 按 `score / max` 映射半径，最低留 4% 避免顶点重叠到圆心 |
| 网格 | 三层五边形（34% / 67% / 100%）+ 五条轴线，颜色用 `--line` 系 |
| 标签 | 名称一行、分值一行（`17/20`，分母小一号灰字），按 `cos` 决定左右对齐，避免出框 |
| 退化 | 维度少于 3 条时不画（画不出面），容器保持 `hidden` |

### 标准模板 PDF

`js/pdf-export.js` 自己排版、自己写 PDF 容器，**不依赖任何库，也不联网**：

1. `Painter` 在 1240×1754 的逻辑坐标系里自上而下流式排版（字号、行高、色板与页面一致），画布按 2 倍（≈300dpi）输出；
2. 每页 `canvas.toDataURL('image/jpeg', 0.92)` 得到 JPEG 字节；
3. 手写 PDF：`/Type /Page` + `/XObject /Subtype /Image /Filter /DCTDecode` + `xref` + `startxref`，A4 595.28×841.89pt。

为什么不嵌字体：中文子集化需要 TrueType 解析与子集生成，纯前端手写不现实；图片型 PDF 换来「任何阅读器都能开、中文不乱码」，代价是文字不可选中。已验证：`pypdf` 读 2 页 / A4 mediabox / 每页 1 张 JPEG / 正文墨迹边距左右各 96pt 内、不越界。

报告内容：总评（分 / 档 / 建议 / 压分说明）→ 五维分（条 + 一句证据）→ 四层诊断（最狠一条 + 怎么改）→ 亮点 → 面试会被这么问（前 6 问 + 答法）→ 逐句改写（优先用你在优化页已生成的那一句，没有就输出骨架与要补的点）→ 规划摘要（定位句 / 缺口词 / 三条证据 / 三张资质 / 3-6-12 月）。

## 深审（阶段 4）：七项逐行体检

审阅页回答「这份简历值多少分」，深审页回答「这一行会被怎么问」。引擎是纯函数：
`AuditEngine.audit(text, { jd, industry, jobTitle })` → 七项分 + 逐行结论 + Markdown，不联网、不调模型。

| 维度 | 权重 | 看什么 | 主要扣分点 |
| --- | --- | --- | --- |
| 详细度 | .24 | 对象 / 动作 / 方法 / 规模 / 结果 五件齐不齐 | 要素缺三块 = 太空；一条只剩「负责…」= 太薄；>90 字 = 太长 |
| 该补的补了没 | .18 | 缺的要素、缺的板块、缺的 JD 关键词 | 板块缺口（技能 / 项目 / 难点）× 结构分 + 逐行缺口密度 |
| 真实性 | .15 | 口径、极端词、职级、团队成果归属、0→1 宣称 | 300% 无基数、圆整百分比、独揽团队成果、职级虚标、奖项含糊 |
| 语言 ai味 | .13 | 行话、自夸形容词、软素质声明、AI 句式 | 同构三连、结论式冒号、不仅…而且、通过…实现、整段自我评价 |
| 追问防御 | .12 | 高危追问是否落在站不住的行上 | risk=3 的追问压在太薄 / 不可信的行上，一问就塌 |
| 该删的删了没 | .11 | 废话、隐私、重复、超长句、兴趣爱好、简历标题 | 隐私字段、薪酬期望、自我评价整段、近重复句（字面重合 >0.6） |
| 逻辑与结构 | .07 | 倒序、重叠、空窗、技能未在正文出现、教育顺序 | 时间线重叠 / 空窗、技能区与经历打架 |

**封顶规则**：七项加权是原始分，但硬伤会压分并写明原因 —— 抬头行（有抬头零内容）≤ 58、详细度 < 40 ≤ 59、写出结果的条目不足 1/4 ≤ 68、≥2 处真实性硬风险 ≤ 66。档位 A ≥ 85 / B ≥ 72 / C ≥ 60 / D。

**逐行七块**（都在 `rows[]`，锚 `line` / `lineNo = line + 1`，`excerpt` 是原文前缀）：

| 块 | 数据 | 说明 |
| --- | --- | --- |
| ① 会被这么问 | `row.ask[]` | 最多 3 条，带 `risk`（1–3）与 `skeleton` 答法骨架；带数的行追问口径，只写工具名的行追问「为什么用它」 |
| ② 够不够细 | `row.detail` | `got` 五要素布尔 + `missing` + `verdict`（合适 / 偏薄 / 太空 / 太薄 / 太长 / 清单） |
| ③ 真不真实 | `row.truth` | `risks[]`（name / why / fix）+ level：clean / mid / high |
| ④ 该补什么 | `row.add[]` | what / why / example —— example 是「填什么」的骨架，不是替你写的句子 |
| ⑤ 该删什么 | `row.cut[]` | what / why / fix，含近重复句 |
| ⑥ 语言与 AI 味 | `row.tone` + `row.strip` | 命中词 + 分组 + 改法；`strip` 是「删词后近似」，机械删词，界面明确标注 |
| ⑦ 逻辑 | `row.logic[]` | 行级时间 / 归属冲突 |

**三件「能照着做」的东西**：

| 能力 | 数据 | 怎么算 |
| --- | --- | --- |
| 先动这三条 | `topActions[]` | 候选按「掉分狠 × 改起来便宜」打分：真实性硬风险 100 > 抬头空段 96 > 逻辑硬冲突 88 > 薄行挂高危追问 90 > 隐私 86 > 整篇 AI 指纹 80；去重（同种动作最多两条）后取前三，每条带 `doThis`、`impactText` 与「跳到这一行」 |
| 可填句式 | `row.pattern` | 每行拆四槽（动作+对象 / 方法 / 规模 / 结果）：已有事实原样搬进句子，缺的槽写成 `[怎么做的]`、`[盘子多大]`、`[改前 → 改后]`；弱动词另给 `verbFix` |
| 改前改后 | `resume-opt.audit.history.v1` | 每次深审存一份指纹（总分 / 七维 / 追问键 / 文本 hash，留 6 份）；下次进来对比「总分 ±N · 追问消掉几条新增几条 · 哪个维度动了」 |

估算要标清楚：`impactText` 里的 +N 是拿当前权重反推的一阶近似（一处真实性硬风险 = 真实性 −22，折到总分约 +3），界面统一标「估」，并附行内变化（「这一行 20 → 80」），免得把估算当承诺。

**职能族：换权重 + 硬门槛** —— `meta.familyArch / meta.familyGate`：

| 族型 | 权重档 | 该族看什么（look） | 盘子口径（scale） | 硬门槛（缺它直接压分） |
| --- | --- | --- | --- | --- |
| 运营 / 销售 / 市场 / 客服 | 结果型 | 你动过哪个指标、动了多少 | 用户数 / 单量 / 签单额 / 回款 | 销售无业绩数字 → ≤62 |
| 技术 / 测试 / 制造 / 建工 / 供应链 | 工程型 | 技术栈、系统规模、模块边界 | QPS / 数据量 / 产线规模 | 技术无技术栈 → ≤66 |
| 财会 / 法务 / HR / 行政 | 规范型 | 账套 / 合同量 / 招聘量 / 流程覆盖 | 账套数 / 合同份数 / 人数 | 证书岗无证书 → 补板块 |
| 设计 / 教育 / 医护 | 表达型 | 作品、风格适配、教研/护理产出 | 项目数 / 学生数 / 床位数 | 设计无作品链接 → ≤68 |

**JD 行级落位** —— `jdMap`：只做关键词对位，不做语义联想。三档：
- 正文有人接（`strong`）：该词在工作/项目条目里有文本证据
- 只在技能区躺着（`skillOnly`）：技能/自评里写了但正文无证据，面试官一问就穿
- 全文没提（`absent`）：只有你真做过才写进对应经历里

**答案质检** —— `AuditEngine.checkAnswer({ answer, kind, rowText, arch })`：用户把面试口头答案写进输入框，引擎只判「还缺什么」，不替你写答案。输出 `score/verdict/missing/flags/followups/assembled/note`；`assembled` 只拼用户给过的字，不产生新事实。

**今日清单** —— `checklist[]`：把「先动这三条 / 高危追问 / 该删」去重合并成 ≤8 条可勾选项，存 `resume-opt.audit.todo.v1`，打印样式只保留顶部「先动这三条」+ 今日清单两页，可存 PDF 贴屏幕边。

**不替你编事实**：引擎只重排事实、指出缺什么，永远不产出「从 18% 提到 41%」这种你没写过的数字；`stripPreview()` 的结果一律标成「删词后近似」。
